# Windows-клиент: установка и подключение к серверу

Сервер Cirvo работает на Linux, пользователи ставят клиент на Windows
(Windows 10 или 11, 64-бит). Клиент общается с сервером только по HTTPS и
WebSocket, отдельного агента на сервере не нужно.

## Что нужно знать оператору перед приглашением

| Что | Пример |
| --- | --- |
| Адрес сервера | `chat.example.com` |
| Логин и пароль или инвайт | выдаёт администратор |
| Открыты порты на сервере | 80/443 TCP, 3478 TCP+UDP, 49160–49200/UDP, 50000/UDP |
| Настроен CORS для Tauri | `CIRVO_CORS_ORIGINS` содержит `http://tauri.localhost` и `https://tauri.localhost` |

Команды проверки: [diagnostics.md](diagnostics.md).

## Установка

1. Получить `Cirvo_<версия>_x64-setup.exe` (см. [desktop-release.md](desktop-release.md)).
2. Запустить установщик от имени администратора.
3. SmartScreen: **Подробнее → Выполнить в любом случае**. Установщик не подписан
   сертификатом издателя.
4. Запустить Cirvo.

### Три разные проверки доверия

- **TLS-сертификат сервера** защищает HTTPS-соединение с вашим сервером. Если
  используется внутренний CA, клиентам передают только его публичный корневой
  сертификат (`root.crt`, см. ниже). Закрытый ключ сервера или CA никому из
  пользователей передавать нельзя.
- **Подпись обновления `.sig`** проверяет, что файл обновления подписан ключом
  Cirvo, которому доверяет клиент. Она уже используется для updater-обновлений
  начиная с 0.2.0 и не удостоверяет имя издателя Windows.
- **Authenticode-подпись** удостоверяет издателя Windows-установщика. У Cirvo
  она пока не настроена. Сертификат TLS сервера и подпись `.sig` её не заменяют.
  Даже Authenticode-подпись не гарантирует исчезновение предупреждения
  SmartScreen: Windows также учитывает репутацию файла и издателя. Подробности:
  [SmartScreen reputation for Windows app developers](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

Если позже подключать сервис подписи кода, он потребует проверки личности или
организации. Например, [требования Microsoft Artifact Signing](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart).

## Первое подключение

1. На экране «Подключение к серверу» ввести адрес: `chat.example.com`.
   Для домена клиент сам подставит `https://`. Для IP-адреса и `localhost`
   подставляется `http://`: если на IP стоит HTTPS, пиши схему явно
   (`https://10.0.0.5`).
2. Нажать «Подключиться». Клиент делает запрос `GET /readyz`.
3. Войти или зарегистрироваться. Если регистрация закрыта, логин и пароль
   выдаёт администратор через «Админ-панель → Пользователи → Создать».
   При временном пароле клиент сначала требует сменить его.
4. Принять приглашение в рабочее пространство: кнопка ввода кода инвайта в
   левой колонке.

Адрес сохраняется локально. Сменить его можно на экране входа («Сменить»)
или в «Настройки → Сервер». Сессии Windows-клиента хранятся в диспетчере
учётных данных Windows отдельно для каждого сервера. Веб-клиент использует
своё браузерное хранилище.

Если порт 443 занят другим сервисом, укажи HTTPS и порт явно, например
`https://<PUBLIC_IP>:8443`. Сертификат должен содержать этот IP в SAN;
переадресация TCP 8443 и доверенный корневой сертификат нужны каждому клиенту.

## Самоподписанный сертификат (`CIRVO_TLS_EMAIL=internal`)

Клиент не умеет принимать недоверенные сертификаты, он использует хранилище
Windows. Если сервер выдаёт сертификат своим внутренним CA, корневой
сертификат нужно один раз установить на каждом компьютере.

1. Забрать корневой сертификат с сервера. Он лежит в volume `caddy-data`:

   ```bash
   docker compose -f deploy/single-node/docker-compose.yml --env-file deploy/.env \
     cp reverse-proxy:/data/caddy/pki/authorities/local/root.crt ./root.crt
   ```

2. На Windows, в PowerShell от администратора:

   ```powershell
   certutil -addstore -f Root .\root.crt
   ```

3. Перезапустить Cirvo.

Если есть возможность, проще использовать домен и Let's Encrypt: тогда
ничего устанавливать не нужно.

## Голос и видео

В «Настройки → Голос и видео» нажми «Разрешить микрофон и показать имена», если список устройств без названий. Затем выбери микрофон и динамики; «Обновить устройства» перечитывает список после подключения или смены разрешений Windows. Для камеры есть отдельная проверка. При уходе с вкладки тестовые потоки останавливаются; отключённое выбранное устройство остаётся явно помеченным, чтобы клиент не начал запись с другого микрофона.

## Обновление клиента

Первый установщик берётся со страницы GitHub Releases. Последующие подписанные
обновления клиент получает с выбранного HTTPS-сервера по адресу
`/updates/latest.json`, с авторизацией Cirvo. Если оператор не разместил новую
версию на сервере, установи новый `setup.exe` вручную поверх старого; данные и
адрес сервера сохранятся. Порядок публикации обновлений описан в
[desktop-release.md](desktop-release.md).

## Чек-лист проверки подключения

Короткая проверка с двумя компьютерами, в том числе через VPN:

- [ ] установщик запускается, приложение открывается;
- [ ] адрес сервера принимается, неверный адрес даёт понятную ошибку;
- [ ] адрес сохраняется после перезапуска;
- [ ] вход, выход и повторный вход работают;
- [ ] сообщение с одного компьютера приходит на другой без перезагрузки;
- [ ] вложение (картинка) загружается и открывается;
- [ ] голосовой канал: слышно друг друга в обе стороны;
- [ ] демонстрация экрана показывается второму участнику;
- [ ] после обрыва сети (выключить Wi‑Fi на 10 секунд) клиент переподключается.
